# Git と GitHub の違い、リポジトリの種類を理解する

はじめて Git や GitHub に触れる人向けの導入ドキュメント。ここで基本のイメージをつかんでから、[01](01_server_bare_repo_create_jp.md) 以降の実践的な手順に進むとスムーズに理解できる。

---

## この文書で学ぶこと

- Git と GitHub は何が違うのか
- 「ローカルリポジトリ」「リモートリポジトリ」「ベアリポジトリ」はそれぞれ何を指すのか

---

## 1. Git と GitHub の違い

### Git とは

Git は「バージョン管理システム」と呼ばれるソフトウェアそのもの。自分の PC にインストールして使う。

- ファイルの変更履歴を記録する
- 過去の状態にいつでも戻せる
- 複数人による変更を統合（マージ）できる
- インターネットに繋がっていなくても、ローカルだけで動作する

### GitHub とは

GitHub は、Git で管理しているリポジトリを置いておくための Web サービス（ホスティングサービス）。

- リポジトリをインターネット上に保管し、他の人と共有できる
- Pull Request、Issue、GitHub Actions など、Git 自体にはないコラボレーション機能を提供する
- 同じ役割のサービスに GitLab、Bitbucket などもある

### まとめ

| | Git | GitHub |
|---|---|---|
| 正体 | バージョン管理ソフトウェア | Web ホスティングサービス |
| 動作する場所 | 自分の PC（ローカル） | インターネット上（クラウド） |
| なくても困る？ | Git がなければ何も始まらない | GitHub を使わず、Git だけで運用することも可能（社内サーバーなど） |
| 主な機能 | 履歴管理・差分・ブランチ・マージ | リポジトリ共有・PR・Issue・CI/CD など |

> **たとえるなら：** Git は「文書の変更履歴を記録する仕組み」そのもの。GitHub は「その文書をオンラインで保管・共有するための場所とサービス」。Git がなければ GitHub は成立しないが、GitHub がなくても Git だけで作業することはできる（このリポジトリの [01](01_server_bare_repo_create_jp.md)・[02](02_server_git_workflow_jp.md) は GitHub を使わない例）。

## 2. リポジトリの種類：ローカル／リモート／ベア

### ローカルリポジトリ

自分の PC 上にある、実際に編集するファイル群（ワーキングツリー）と `.git` フォルダの両方を持つリポジトリ。ここでファイルを編集し、`git add` → `git commit` して変更履歴を積み重ねていく。

### リモートリポジトリ

「リモート」とは、自分のローカルリポジトリから見て **push / pull する相手先** を指す一般的な言葉であり、リポジトリの種類そのものを表すわけではない。相手先の実体が何であるかは問わない。

- サーバー上に自分で作ったベアリポジトリ
- GitHub 上のリポジトリ
- 同僚の PC 上のリポジトリ

これらはすべて `git remote add` でローカルに登録すれば「リモート」として扱われる。つまり「リモートリポジトリ」＝「ローカルの外側にあって、push/pull で同期する相手」という位置関係を表す呼び方。

### ベアリポジトリ

ワーキングツリー（実際に編集するファイル本体）を持たず、`.git` の中身だけで構成されるリポジトリ。`git init --bare` で作成する。

- 誰かが直接ファイルを編集する場所ではない
- 複数人が push / pull し合うための「共有の置き場」として使う
- 実は GitHub 上のリポジトリも、内部的にはこのベアリポジトリと同じ仕組みで管理されている

つまり「GitHub リポジトリ」は、「クラウド上に置かれたベアリポジトリ＋PR や Issue などのコラボレーション機能」と考えるとイメージしやすい。

### 3つの関係を図にすると

```
[ローカルリポジトリ]                      [リモートリポジトリ]
~/example/  （ワーキングツリーあり）        いずれかの実体：
  ex.py                                   ① 自分でサーバーに作るベアリポジトリ
  .git/                                      （01, 02 で解説）
        -- git push -->                   ② GitHub 上のリポジトリ
        <-- git pull --                      （03, 04 で解説）
```

| 種類 | ワーキングツリー | 主な用途 | 関連ドキュメント |
|---|---|---|---|
| ローカルリポジトリ | あり | 実際にファイルを編集・コミットする | - |
| ベアリポジトリ（自前サーバー） | なし | push/pull 用の共有場所を自分で用意する | [01](01_server_bare_repo_create_jp.md), [02](02_server_git_workflow_jp.md) |
| GitHub リポジトリ | なし（Web ブラウザで内容は閲覧できる） | push/pull 用の共有場所＋PR・Issue 等の機能 | [03](03_github_push_jp.md), [04](04_multi_remote_jp.md) |

> **補足：** 「リモート」はあくまで役割の呼び方なので、1つのローカルリポジトリに対して、社内のベアリポジトリと GitHub の両方を別々の「リモート」として登録することもできる。この応用パターンは [04](04_multi_remote_jp.md) で扱う。
